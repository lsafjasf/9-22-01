## 语言与增量策略

行导向小语言：`let  ident = expr ;`、`expr ;`、`# 注释`，表达式含 `= - + * / ( )`。
文档按物理行缓存子树；一次编辑 `[start, end) -> ins` 只重解析与编辑区间
相交的旧行 `[l0, l1]`（映射到新文本后的对应行），`l0` 之前的行原样复用，
`l1` 之后的行深拷贝并按**本次** delta 平移。每次编辑在 `last_reparse`
中记录 `ReparseInfo(start, end, lines_reparsed, total_lines, delta)`。

## 三类症状的成因与修复

### 症状 1：补全左括号后整份文件位置整体偏移 —— 位置偏移的累加方式错误

- **成因**（`parser_buggy.py` 的 `BUG 1`）：缺陷版维护一个全局累加器
  `self._shift += delta`，并把**累计值**施加到**所有**复用节点上——
  既包括编辑点之前、本不该移动的节点，也包括已经被上次编辑平移过、
  本次被重复累加的节点。于是插入一个 `(` 后，全文位置一起漂移，
  且每次编辑漂移量不断复利。
- **修复**（`parser_fixed.py` 的 `edit`）：只有 `l1` 之后的行才按
  **本次编辑的** `delta = len(ins) - (end - start)` 平移（`with_shift`
  返回深拷贝，不污染旧树）；`l0` 之前的行不做任何位移。没有累加器。

### 症状 2：删除注释后语法树残留旧节点 —— 节点复用的边界判定错误

- **成因**（`BUG 2`）：缺陷版只用编辑**起点**做严格比较来分类旧行
  （`e < start` 才算前缀、`s >= start` 就算后缀平移复用），从不检查
  节点是否与被删除区间相交。被删注释行的起点恰好 `>= start`，于是被
  当作"编辑点之后"的节点平移保留——旧节点残留；同时 `e == start` 的
  相邻行两边都不满足而被静默丢弃。
- **修复**：用旧文本中精确的影响区间 `[l0, l1]` 划分——`l0` 为包含
  `start` 的行，`l1` 为包含 `end` 的行（行的终止换行符属于该行：
  删除范围落在行边界上会合并下一行，因此用 `end` 而非 `end - 1`
  定位 `l1`，否则撤销/重做场景会出现节点与行错位）。区间内的行一律
  重新词法/语法分析，绝不复用；区间之外的行才允许复用。

### 症状 3：一次错误恢复失败后同一文件永远返回同一份错误结果 —— 缓存污染

- **成因**（`BUG 3`）：缺陷版有一个模块级字典 `_POISON_CACHE`，按文档
  id 缓存"产生过错误"的解析结果；一旦某次解析走了错误恢复路径，之后
  同一文档的每次解析（包括文本已修复之后）都被替换成缓存的旧错误结果。
- **修复**：错误恢复是当前文本的**纯函数**——没有任何跨解析的可变
  状态、没有全局/按文档的缓存。同一个错误输入每次解析都得到相同的
  语法树与相同的错误列表（可重现），修复文本后立即得到正确结果
  （不粘连）。`test_error_recovery_is_reproducible_and_not_sticky`
  同时验证这两点。

## 一致性对拍方法

`parser_core.tree_key` 把每棵树折成包含 `kind / [start, end) / value /
errors / children` 的嵌套元组；每次编辑后用 `first_mismatch` 将增量树与
`parse_full(当前文本)` 的全量树**逐节点逐位置**比较（不只比文本）。
覆盖：括号补全、注释增删、多处同时编辑（`apply_edits` 批量）、
撤销/重做（逆编辑回放）、300 步种子化随机模糊（另用 2000 步脚本验证过）。
`TestReparseRange` 断言 400 行文件中的单字符编辑只重解析 1 行，
重解析范围远小于全文，不退化为整文件重解析。
